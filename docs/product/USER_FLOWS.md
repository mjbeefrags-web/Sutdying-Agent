# Core user flows

## First study session
1. Sign up and verify email → create a course → see private-by-default notice.
2. Upload a PDF/TXT → validate type/size → show queued, processing, ready, or actionable failure.
3. Open course workspace → browse source list and processing details.
4. Ask a question → retrieve only authorized course chunks → receive answer with page citations or a clear insufficient-evidence response.
5. Open cited source passage → create a flashcard or practice question → save/edit → review.

## Exam preparation
Choose course and exam date → review due cards and recent mistakes → take a bounded practice set → review answer explanations and sources → accept/edit a suggested weekly plan. Student confirms plan changes; no autonomous calendar writes.

## Library navigation
Open library → browse course shelves in 3D or accessible list → select course → continue to the same course workspace. 3D failure, reduced-motion preference, or low-capability device switches to 2D without loss of context.

## Account and content lifecycle
Settings → export data or delete one document/course/account → confirm destructive action → revoke sessions and queue data/vector/object deletion → show completion status. Billing controls appear only when real payment integration is enabled.

## Recovery paths
Network interruption preserves the draft and allows retry; duplicate upload is identified by content hash within the student's scope; unavailable AI providers leave saved content usable and offer retry. Never render a successful answer/job state on timeout.
